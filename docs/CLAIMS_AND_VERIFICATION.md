# Claims and verification

## Use precise terms

- **Observation** — what a current run or owning system actually returned.
- **Measurement** — a quantity such as time, bytes, calls, queue depth, or
  resource use, with a source and time range.
- **Check** — a deterministic predicate over explicit inputs.
- **Assessment** — a person, reviewer, or model mapping current facts to
  criteria and stating remaining uncertainty.
- **Gate** — an enforced boundary that consumes predefined checks and actually
  blocks or permits one named action.
- **Proof** — a formal proof object or a deliberately narrow certified
  property. Ordinary tests and reports are not proofs.

Use the word evidence only inside one named current logic chain for one explicit
claim, with provenance, freshness, inference, and residual uncertainty stated.
The label itself grants no authority.

## Current public claims

The public core supports these bounded claims:

- Capability and Procedure document families have closed schemas, reference
  validators, executable negative tests, and current provider-seeded catalogs.
- Direct Execution Runtime has a source implementation for validated read-only
  Capability, Procedure, and MCP calls, including a local current-user service.
- Current maintainer-local pilots exercise the architecture on one macOS
  machine through real provider boundaries.
- The repositories are independently licensed, tested, security-scanned, and
  releasable from source.

## Claims not made

The public release does not establish:

- compatibility with every Agent shell, operating system, device, or provider;
- that natural-language routing will select the intended tool in every session;
- cross-provider substitution for a Profile with only one provider;
- that a Procedure is the best professional method for every organization;
- production capacity, an SLA, or universal token/cost savings;
- side-effect authorization, credential safety, or operating-system sandboxing;
- correctness of a provider merely because it generated a result or report;
- that related systems are inferior or that this architecture is the only way
  to separate reasoning from execution.

## Performance claims

Report cold Agent, cold direct, warm direct, and provider-native batch as
separate routes. State the machine, workload, revision, provider version,
sample size, concurrency, result bytes, model calls, and unobserved costs. Do
not turn one provider's timing into a universal savings percentage.

## Freshness

Every later Agent or reviewer must reacquire the current branch, dirty state,
schemas, provider manifests, installed bindings, credentials/permissions, live
endpoint health, and relevant external facts. A prior closeout is an index, not
current authority.
